## Design

### 1. Make core-change authority unambiguous

Use the normal repository workflow for Olympus core changes. Olympus dogfood can supply evidence, but it cannot govern the core repair. A standing directive cannot satisfy an owner-in-own-reply gate.

Delete the tracked `.olympus/tasks/*.md` transcripts. They are historical, non-conforming records and Git already preserves them. Retain only concise, verified evidence in `docs/CONFORMANCE.md`.

### 2. Repair the existing specification contract

- Let each reviewer record `no-prior-repair` when no earlier body bytes changed. After a real repair, both reviewers must run L6 against the changed body.
- Apply the documented default when a PROJECT boundary-setting row is absent. Record the effective value at goal start. This rule covers both `strict convergence` and `writer reuse`.
- Give each reviewer the assigned lenses and current task metadata. Require one disposition for each assigned lens.
- Use `no-frozen-ledger` as the exact ledger state before round 1. Store any first-result cap proposal in the task cap-amendment record before review.

### 3. Remove the Writer-residue state machine

Keep Writer reuse and the three self-tests. If a final self-test still finds an adverse result, return `blocked`. Do not return an eligible body with residue.

Remove residue supersession, residue acceptance, cap-close residue reporting, and the forced restatement path. This is a net deletion and removes the main source of late Fix 5 P1 defects.

### 4. Bound divergence

Reuse the existing finding ledger. Do not add a second metrics system.

After lens coverage completes, permit at most one further Writer result while the latest frozen ledger holds an open P0 or P1. If the next consumed round still holds an open P0 or P1, block the goal and stop Writer dispatch. Recovery requires an owner-issued narrowed or replacement goal with a new sizing check.

This control limits the maximum blast radius. It does not prove better Writer quality.

### 5. Validate and release

Add deterministic conformance cases for:

- clean-body L6 disposition;
- changed-body L6 review;
- missing lens input or disposition;
- omitted boundary settings;
- first-result cap refusal and grant;
- adverse Writer self-test blocking;
- two-round divergence blocking;
- bounded Fix 1 Claude evidence.

Run a Ponytail review for unnecessary additions and a Resilience review for changed failure surfaces. Require no material unresolved finding before release.

Update the version and release documents. Create `v0.5.1` only from the verified remote `main` commit after all corrective changes merge. Publish matching GitHub release notes. Leave issues #17-#19 and #23 open for v0.6.

## Recovery and release safety

- Keep the canonical dirty checkout untouched.
- Use named-file staging only.
- Stop if the reviewed commit changes before merge or tagging.
- Reconcile remote branch, tag, and GitHub release state before retrying an ambiguous action.
- Do not move an existing tag. Delete no remote state during recovery.
